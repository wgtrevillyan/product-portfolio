# William Trevillyan's Product Portfolio

A static portfolio site showcasing products, companies, patents, and skills. Content is driven by JSON in `data/` and injected client-side; assets are local (no Webflow CDN dependency).

**Live site:** [trevillyan.dev](https://www.trevillyan.dev)

## Tech Stack

- **Frontend:** Static HTML, CSS (originally from Webflow export), vanilla JavaScript
- **Content:** JSON in `data/` loaded by `js/cms-data.js` and rendered into the DOM
- **Assets:** Images and SVGs in `images/` (companies, products, patents, product-images)
- **Hosting:** Vercel (static files + serverless API)
- **Contact form:** Vercel serverless function (`api/contact.js`) using Nodemailer + Gmail SMTP

## Getting Started

### Prerequisites

- **Node.js 18+** (for build scripts and optional local dev)
- **npm**
- **Vercel CLI** (optional, for `vercel dev` with rewrites)

### Install

```bash
npm install
```

### Build

```bash
npm run build
```

The build runs:

1. **Header injection** — Injects `components/header.html` into each page with correct nav highlighting
2. **Footer injection** — Injects `components/footer.html`
3. **Clean URLs** — Replaces `.html` links with path-based URLs
4. **Root asset paths** — Converts relative asset paths to root-relative (required for clean URLs like `/products/clip360`)
5. **Analytics injection** — Injects PostHog + an AI-referral helper into every page's `<head>` (see [Analytics](#analytics))
6. **Sitemap** — Generates `sitemap.xml` from static routes and `data/*.json` (companies, products, patents)
7. **Detail pages** — Generates per-slug static HTML for **products** (`product_pages/`), **companies** (`company_pages/`), and **patents** (`patent_pages/`) with correct title/description/Open Graph/Twitter/canonical meta, entity **JSON-LD**, and a crawler-visible `<noscript>` summary (the live pages are otherwise client-rendered). Converts WebP thumbs to PNG in `images/<type>/og/` for og:image (LinkedIn supports only PNG/JPEG/GIF). Updates `vercel.json` with per-slug rewrites so `/products|companies|patents/:slug` serve the generated files.
8. **Homepage JSON-LD** — Injects a `Person` / `ProfilePage` / `WebSite` `@graph` into `index.html`
9. **AI artifacts** — Generates `llms.txt`, `llms-full.txt`, and per-entity Markdown mirrors (see [AI discoverability](#ai-discoverability-seo--geo--aeo))

### Development

Run the site locally with Vercel’s dev server (rewrites and serverless routes work as in production):

```bash
vercel dev
```

Install the [Vercel CLI](https://vercel.com/docs/cli) if needed: `npm i -g vercel`.

### Environment Variables

For the contact form, set these in the Vercel project (or in `.env.local` when using `vercel dev`; `.env*.local` is gitignored):

| Variable | Description |
|----------|-------------|
| `SMTP_USER` | Gmail address (e.g. `no-reply@yourdomain.com`) |
| `SMTP_APP_PASSWORD` | Gmail App Password (not your normal password) |
| `NEXT_PUBLIC_POSTHOG_TOKEN` | PostHog project API key (public client-side key). Baked into the HTML at build time. Omit to disable PostHog (Mixpanel-only). |
| `NEXT_PUBLIC_POSTHOG_HOST` | PostHog host. Defaults to `/ingest` — the first-party reverse proxy (see [Analytics](#analytics)). Set to `https://us.i.posthog.com` to bypass the proxy. |

## Clean URLs

The site uses path-based URLs instead of `.html`:

| URL | Serves |
|-----|--------|
| `/` | Home |
| `/products` | Products list |
| `/products/clip360` | Product detail (by slug) |
| `/companies` | Companies list |
| `/companies/property-meld` | Company detail |
| `/patents` | Patents list |
| `/patents/:slug` | Patent detail |
| `/let-us-chat` | Contact form |

## Sitemap

The build generates `sitemap.xml` with all public URLs (home, list pages, and each company/product/patent detail). Default base URL is `https://www.trevillyan.dev`; override when building for another domain:

```bash
SITE_URL=https://example.com npm run build
```

Submit [trevillyan.dev/sitemap.xml](https://www.trevillyan.dev/sitemap.xml) in Google Search Console (or similar) for indexing.

## AI discoverability (SEO / GEO / AEO)

The site is built to be readable and citable by both classic search crawlers and AI answer engines (ChatGPT, Claude, Perplexity, Google AI Overviews). Generated by the build from `data/`:

| Artifact | Purpose |
|----------|---------|
| `robots.txt` | Crawler policy — **allows** answer engines (OAI-SearchBot, ChatGPT-User, Claude-User/SearchBot, PerplexityBot, Applebot) and the general web; **disallows** AI *training* crawlers (GPTBot, Google-Extended, ClaudeBot, CCBot, Bytespider, …). Declares the sitemap. Static file (not generated). |
| `llms.txt` | Curated, token-efficient overview + index of all companies/products/patents ([llmstxt.org](https://llmstxt.org)). |
| `llms-full.txt` | The overview with every entity's content inlined — one-fetch context for agents. |
| `index.md`, `companies/<slug>.md`, `products/<slug>.md`, `patents/<slug>.md` | Clean Markdown mirrors of each page (the HTML pages are client-rendered Webflow shells; these give agents the real content). |
| JSON-LD | `Person`/`ProfilePage`/`WebSite` `@graph` on the homepage; `Organization` (companies), `SoftwareApplication` (products), `CreativeWork` (patents) on detail pages. |
| `<noscript>` summaries | Minimal name + description + highlights on each detail page for non-JS crawlers. |

Regenerate just the LLM artifacts with `npm run build:llms`. All of the above honor `SITE_URL` for alternate domains.

> **Note on roles:** the `Organization` JSON-LD intentionally does **not** assert a founder/employee relationship, because Bill founded some companies (NewsNook, Verbaly, Trevillyan Labs) but was an employee at others (Clip Automation, Incode, Property Meld). Add a per-company role mapping before claiming `founder`.

## Analytics

`scripts/inject-analytics.js` injects, into every page, **PostHog** (the going-forward analytics) plus a small **AI-referral** helper that detects visitors arriving from AI answer engines and fires an `ai_referral` event + `ai_source` super-property to **both PostHog and Mixpanel** during the transition. Mixpanel and LogRocket (inline in the page `<head>` from the original export) are being retired — LogRocket first, then Mixpanel once PostHog parity is confirmed.

The PostHog project token is read from `NEXT_PUBLIC_POSTHOG_TOKEN` at build time (a public client-side key, injected rather than committed). With no token (local builds) PostHog is skipped and the helper still fires to Mixpanel — nothing breaks. Crawlers don't run JS, so this measures *humans arriving from AI answers*, not crawl/citation hits — watch Vercel access logs for the AI bot user-agents.

**Reverse proxy (`/ingest`).** PostHog events are sent through a first-party `/ingest` path rather than directly to `*.posthog.com`, so browser ad/tracking blockers can't drop them — important for capturing inbound referral/UTM traffic (e.g. links tagged `?utm_source=trevillyanlabs.io&utm_medium=referral&utm_campaign=studio_site`). `vercel.json` rewrites `/ingest/*` to PostHog's US ingestion and asset hosts; the snippet's `api_host` defaults to `/ingest` (override via `NEXT_PUBLIC_POSTHOG_HOST`). This mirrors the NewsNook marketing-site setup.

## Content Management

Do **not** edit the generated JSON files directly.

- **Companies**: edit YAML source files in `data/companies/*.yaml` (rich-text fields are Markdown). Then run `npm run build:data` (or `npm run build`) to regenerate `data/companies/companies.json`.
- **Products**: edit YAML source files in `data/products/*.yaml` (rich-text fields are Markdown). Then run `npm run build:data` (or `npm run build`) to regenerate `data/products/products.json`.
- **Other datasets** (patents, skills, tags, product images): currently remain as JSON in `data/` (and `data/products/product-images.json`).

See [data/README.md](data/README.md) for details and image migration (`npm run download-assets`).

## Scripts

| Script | Description |
|--------|-------------|
| `npm run build` | Full build: header/footer/analytics injection, clean URLs, root asset paths, sitemap, per-slug detail pages (meta + JSON-LD), homepage @graph, and AI artifacts (`llms.txt`, mirrors) |
| `npm run build:header` | Inject shared header only |
| `npm run build:footer` | Inject shared footer only |
| `npm run build:data` | Regenerate `data/products/products.json` and `data/companies/companies.json` from YAML |
| `npm run build:llms` | Regenerate `llms.txt`, `llms-full.txt`, and Markdown mirrors only |
| `npm run cleanup` | Replace full header/footer markup with placeholders (one-time cleanup) |
| `npm run download-assets` | Download Webflow CDN assets to `images/` and point JSON at local paths |
